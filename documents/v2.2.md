# 🔐 Version 2.2 - Security & Invoice Updates
**Date:** 2025-12-26

## 🚀 Key Updates

### 🔄 JWT Auto-Refresh Authentication
- **Problem**: Users were forced to log in every hour due to short-lived access tokens.
- **Solution**: Implemented a secure **Refresh Token** mechanism.
    - **Access Token**: Valid for 1 hour (short-lived, secure).
    - **Refresh Token**: Valid for 7 days (long-lived).
    - **Auto-Renewal**: The frontend now automatically detects expired sessions (401 errors) and transparently refreshes the token in the background without interrupting the user.
    - **Implementation**:
        - Backend: Added `AuthModel::refreshToken` and `POST /api/auth/users/refresh` endpoint.
        - Frontend: Updated `common.js` `apiRequest` to handle retries and `auth.js` to store refresh tokens.

### 🧾 Invoice Print Enhancements
- **Dynamic Footer Brands**:
    - The "Frames", "Lenses", and "Contact Lenses" sections in the invoice footer are now dynamically populated with data from the invoice (using `frame`, `lence`, and `contact_lence` fields).
    - Defaults to empty if no data is present.
- **Bootstrap Toolbar Reversion**:
    - Reverted the print toolbar to the classic simple design as per user preference.
    - Restricted paper size selection to **A5** only.

## 🛠️ Technical Details
- **Database**: No schema changes required for refresh tokens (JWTs are stateless).
- **Security**: Refresh tokens are stored in `localStorage` and exchanged for short-lived access tokens.
